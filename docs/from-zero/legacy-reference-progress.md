## 1. 文档目的

本文跟踪 NovaAgent 在从零建设过程中，对现有 CowAgent 能力的调研、参考、复用、兼容和覆盖情况。

这是一份辅助进度表，不是功能建设路线。阶段顺序、架构边界和验收目标以 `00-overall-roadmap.md` 及各阶段 `design.md` 为准。CowAgent 的目录和实现不能反向决定 NovaAgent 的模块划分或开发顺序。

下文“当前项目参考”统一指只读参考项目 CowAgent；“新系统”统一指 NovaAgent。

本文主要回答：

1. 当前 CowAgent 已有哪些值得参考的能力？
2. 这些能力计划在哪个新系统阶段建设？
3. 对应旧实现采用全新设计、参考重写、选择性复用、兼容适配还是明确废弃？
4. 新系统是否已经完成设计、实现、测试、运行验证和验收？
5. 旧配置、工作空间、数据和用户行为是否需要兼容？

## 2. 更新规则

- 创建阶段设计文档时，更新相关行的设计状态和预期处理方式。
- 开始编码时，将实现状态改为“实现中”，不得提前标记“已实现”。
- 自动化测试通过后记录测试类型和验证命令。
- 实际运行并完成演示后才能标记“已验收”。
- 阶段完成报告必须引用本表中被更新的能力编号。
- 如果实际设计改变了处理方式，先更新阶段设计文档，再更新本表。
- “暂不建设”和“明确废弃”必须在对应阶段设计或 ADR 中说明原因。
- 没有代码、测试或运行记录作为证据时，不得将状态标记为完成。

## 3. 状态定义

### 3.1 设计状态

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚未进入对应阶段设计 |
| 调研中 | 正在核对用户需求、旧行为和约束 |
| 设计中 | 正在编写对应阶段 `design.md` |
| 已确认 | 设计、边界和验收标准已经确认 |
| 不适用 | 该能力明确不进入新系统 |

### 3.2 实现状态

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚未开始新代码实现 |
| 实现中 | 正在完成最小实现 |
| 已实现 | 设计范围内代码已经完成，但不代表已验收 |
| 暂不建设 | 当前路线内保留能力位置，但本轮不实现 |
| 明确废弃 | 经设计确认不再保留 |

### 3.3 测试与验收状态

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚无对应验证 |
| 测试中 | 正在补充或运行自动化测试 |
| 已测试 | 设计要求的自动化测试已通过 |
| 待验收 | 自动化测试通过，等待实际运行或演示 |
| 已验收 | 实际运行和可复现演示均已完成 |
| 受限验收 | 因外部账号或平台限制，只完成可控范围验证，限制已记录 |
| 不适用 | 该能力已明确排除，不需要测试或验收 |

## 4. 旧实现处理方式

| 处理方式 | 使用条件 |
| --- | --- |
| 全新设计 | 新系统问题定义或边界与旧实现不同，不继承内部结构 |
| 参考行为后重写 | 保留用户可见行为和成熟边界场景，使用新协议重新实现 |
| 选择性复用 | 提取相对独立且经过测试的算法、安全校验或格式处理 |
| 适配复用 | 在新 Port 后包装已有 SDK 交互或平台客户端 |
| 数据导入 | 新系统采用新数据模型，通过显式导入器读取旧数据 |
| 兼容封装 | 在系统边界临时接受旧配置或旧调用方式，内部立即转换 |
| 暂时沿用 | 为控制阶段范围短期调用旧实现，必须记录替换阶段 |
| 明确废弃 | 旧能力、旧协议或旧结构不再保留，并记录替代方式 |
| 待阶段设计 | 尚未完成对应阶段设计，不提前承诺处理方案 |

一项能力可以组合多种方式，例如“参考行为后重写 + 数据导入”，但必须分别说明代码处理和数据处理。

## 7. 旧插件体系处理预案

当前 `plugins/` 属于早期扩展体系，与 Agent Tools 和 Skills 存在能力重叠。暂不按插件目录逐个搬运，而按用户价值分流：

| 旧插件类型 | 示例 | 初步归属 | 初步处理 |
| --- | --- | --- | --- |
| 命令与管理能力 | `godcmd`、`cow_cli` | Web 管理用例 / 非聊天管理 CLI | 参考用户行为后重写 |
| 关键词和内容过滤 | `keyword`、`banwords` | Web 输入前处理或 Policy | 随 Web 控制台设计，不复用全局事件总线 |
| 角色与提示词 | `role` | 工作空间与 Prompt | 转化为工作空间能力或 Skill |
| 外部服务封装 | `linkai`、`tool` | Provider / Tool Adapter | 按对应 Port 适配 |
| 示例和娱乐功能 | `hello`、`dungeon` | 示例 Skill | 仅在有教学价值时重建 |
| 旧插件事件总线 | `plugins/event.py` | Application Event / Hook | 不直接沿用，是否需要 Hook 在阶段设计中决定 |

该表将在 Skills、Web 控制台和交付阶段进一步细化。任何旧插件只有映射到明确的新系统用例后，才进入实现计划。
